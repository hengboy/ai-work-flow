| 功能/关键词 | 入口路径 | 模块边界 |
| --- | --- | --- |
| CLI 安装、初始化、验证、生成 | `agent-build/install.mjs` -> `agent-build/runtime/workflow.mjs` | CLI 转交 `runCli`；安装时补齐完全缺失的 Planning、Planning Writer、Task Planner 或 Bug Fixer 配置，将旧 `git-committer` 环境键迁移为 `git-operator`，并把迁移、核心 runtime/资产与平台代理生成放入同一事务；`generate` 在同一事务刷新共享 ReviewManifest runtime 与 agents；安装和生成还通过固定 allowlist 清理已停用的受管理 Skill 目录及状态机文件；`validate`/`generate` 对完全缺失的 Bug Fixer 只使用内存默认值且不改写环境，已有但残缺的配置失败。 |
| 工作流命令、环境管理 | `agent-build/runtime/workflow.mjs` | 依赖 `agent-build/runtime/config.mjs`、`agent-build/runtime/transaction.mjs`、`agent-build/runtime/asset-catalog.mjs`、`agent-build/runtime/paths.mjs`、`agent-build/runtime/platform-adapter.mjs`；托管 Skill 目录通过目录事务与配置、资产和 Agent 共同提交。 |
| Agent 角色、Control、Policy、路由资产 | `agent-build/config/roles.json`、`agent-build/config/controls.json`、`agent-build/config/policies.json`、`agent-build/config/routing.md`、`agent-build/templates/*.md` | controls 提供稳定 ID、显式约束和 Policy 要求；13 个角色使用统一六阶段模板与受管占位，编译后注入控制章节和 JSON handoff。routing 继续管理跨角色治理；Asset catalog 校验控制引用、Policy 一致性、section 分配、状态表、人工门禁与 53,000 字符上限。 |
| 平台 Agent 生成、能力与控制报告 | `agent-build/runtime/platform-adapter.mjs`、`agent-build/runtime/workflow.mjs` | 生成三平台 Agent 配置与托管内容；`CAPABILITY` 后输出逐角色 `CONTROL` 与非 enforced 警告，多个 capability 采用最弱级别。OpenCode 强制 Researcher 的 `.ai-work-flow/research/*.md` 路径；动态单目标和阶段顺序仍为 instruction-only。 |
| 项目上下文与代码导航联合初始化 | `skills/init-ai-work-flow/SKILL.md` | 首次使用项目代码导航或首次进入目录式 ReviewManifest 审查前，基于真实仓库资料联合初始化根 `MEMORY.md` 与 `.ai-work-flow/index/`；不属于 `agent-build install.mjs init`。 |
| 项目代码导航规则 | `skills/project-code-navigation/SKILL.md` | File Explorer 是所有文件检索与只读定位的唯一执行角色；Full Stack Coder 只在实现期间维护 `.ai-work-flow/index/`。 |
| Spec-first 目录式规划与任务 | `agent-build/templates/planning.md`、`agent-build/templates/planning-writer.md`、`agent-build/templates/task-planner.md` | 调用顺序固定为共享理解确认 -> 写入/校验 spec 与原始字节摘要 -> 用户确认 `task_mode: split\|single` -> 写入/校验 digest-bound plan；模式确认前禁止 plan/tasks。plan 只承载实施上下文，不重复 spec 的需求内容。`split` 才生成草案并在颗粒度确认后按 plan digest 全量替换 tasks；`single` 不生成 tasks，仅可在单独确认后删除旧 tasks。Planning 与 File Explorer 校验模式绑定，旧平铺、plan-only 与失效 tasks 均 fail closed。 |
| 计划实施与 bug/finding 修复路径 | `agent-build/templates/coding.md`、`agent-build/templates/full-stack-coder.md`、`agent-build/templates/bug-fixer.md`、`agent-build/templates/git-operator.md`、`agent-build/templates/code-reviewer.md` | Coding 的唯一状态表定义输入、角色、自动下一步与暂停条件；用户直接报告的 bug 必须委派 Bug Fixer，输入不足由 Bug Fixer 按门禁阻塞，普通实现委派 Full Stack Coder。Git Operator 在 commit/sync 成功后 prepare ReviewManifest envelope，Coding 验证交接，Code Reviewer 独立 verify 并编排双轴审查；获批 finding 修复后不执行第二次评审。 |
| Git 路径、审查清单与 runtime provenance | `execution-runtime/lib/{paths,git,review-manifest,directory-review-manifest,runtime-provenance}.mjs`、`execution-runtime/{review-manifest-cli.mjs,runtime-provenance.json}` | `paths` 定义并比较 PathChange，`git` 解析结构化 Git 状态；`review-manifest` 保持既有 digest、双轴分片和 coverage；`runtime-provenance` 校验可移植 source/installed provenance 与受管文件摘要。Git Operator 使用安装 CLI prepare 后立即 verify 唯一完整 envelope，Coding 原样转交，Code Reviewer 独立 verify Git facts与两阶段证据。absent 输入不接收 mode/spec/plan/task 路径，生成 single 空来源 bundle。 |
| 测试 | `test/{agent-workflow,directory-review-manifest,path-change-review-manifest}.test.mjs`、`package.json` | `package.json` 的 `test` 脚本使用 Node 测试运行器；共享 runtime 的目录 bundle、envelope、CLI、Git 与 PathChange 回归测试位于根测试目录。 |
