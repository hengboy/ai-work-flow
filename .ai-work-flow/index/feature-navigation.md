| 功能/关键词 | 入口路径 | 模块边界 |
| --- | --- | --- |
| CLI 安装、初始化、验证、生成 | `agent-build/install.mjs` -> `agent-build/runtime/workflow.mjs` | CLI 转交 `runCli`；安装时补齐完全缺失的 Planning、Planning Writer、Task Planner 或 Bug Fixer 配置，将旧 `git-committer` 环境键迁移为 `git-operator`，并把迁移、核心 runtime/资产与平台代理生成放入同一事务；`validate`/`generate` 对完全缺失的 Bug Fixer 只使用内存默认值且不改写环境，已有但残缺的配置失败。 |
| 工作流命令、环境管理 | `agent-build/runtime/workflow.mjs` | 依赖 `agent-build/runtime/config.mjs`、`agent-build/runtime/transaction.mjs`、`agent-build/runtime/asset-catalog.mjs`、`agent-build/runtime/paths.mjs`、`agent-build/runtime/platform-adapter.mjs`；托管 Skill 目录通过目录事务与配置、资产和 Agent 共同提交。 |
| Agent 角色、Policy、路由资产 | `agent-build/config/roles.json`、`agent-build/config/policies.json`、`agent-build/config/routing.md`、`agent-build/templates/*.md` | 13 个受管理角色包含 Planning、Task Planner、Researcher、Coding、Bug Fixer、Git Operator 和 Code Reviewer；Planning governance 共享 spec-first 工件、摘要绑定和旧格式拒绝不变量；Bug Fixer 只修复可复现 bug 或用户明确批准的当前 blocking finding IDs；Asset catalog 在平台写入前校验关键规划模板契约。 |
| 平台 Agent 生成 | `agent-build/runtime/platform-adapter.mjs` | 生成三平台 Agent 配置与托管内容；Planning 为无直接文件访问的协调角色；OpenCode 将 Planning Writer 限制到目录式 `spec.md`/`plan.md`，Task Planner 限制到 `tasks/??-*.md`，Researcher 限制到 `.ai-work-flow/research/*.md`，单次 Writer 目标和阶段顺序仍为 instruction-only。 |
| 项目代码导航规则 | `skills/project-code-navigation/SKILL.md` | 维护 `.ai-work-flow/index/` 下的功能导航。 |
| Spec-first 目录式规划与任务 | `agent-build/templates/planning.md`、`agent-build/templates/planning-writer.md`、`agent-build/templates/task-planner.md` | 固定工件为 `plans/<plan-id>/spec.md` 与 digest-bound `plan.md`；先确认共享理解，再写/校验 spec 和原始完整字节 SHA-256，之后才写 plan。拆分任务经颗粒度确认后按 plan digest 全量替换；不拆分经删除确认后清空旧 tasks。旧平铺、plan-only 与失效 tasks 均 fail closed。 |
| 计划实施与 bug/finding 修复路径 | `agent-build/templates/coding.md`、`agent-build/templates/full-stack-coder.md`、`agent-build/templates/bug-fixer.md`、`agent-build/templates/git-operator.md`、`agent-build/templates/code-reviewer.md` | Coding 先验证 spec/plan 路径、状态和原始字节摘要绑定；单任务只委派一个 Full Stack Coder，拆分按依赖前沿执行且每个 task 必须绑定当前 plan digest；首次双轴评审的 blocking findings 仍须用户确认具体 IDs，修复后的新后继 review commit 经关系、HEAD、同步和后续前置条件验证后自动用于 task 汇入或最终整合，不再进入复审选择；冲突解决后的重新评审规则不变。 |
| Spec、Ticket 执行 | `execution-runtime/execution-cli.mjs`、`skills/run-matt-spec-to-completion/lib/execution-coding.mjs` | CLI 是 prepare/claim/record/sync/review/fix/integrate/cleanup/status 的唯一状态入口；同步冻结 `main_commit`，冲突由实施角色解决。 |
| Ticket Handoff、Git 路径与审查清单 | `skills/run-matt-spec-to-completion/lib/{paths,git,review-manifest}.mjs` | `paths` 定义并比较 PathChange，`git` 唯一解析 porcelain v2 `-z`，`review-manifest` 冻结 digest、双轴分片和 coverage。 |
| 执行计划、Checkpoint | `execution-runtime/state-store.mjs`、`skills/run-matt-spec-to-completion/lib/checkpoint.mjs`、`skills/run-matt-spec-to-completion/lib/checkpoint-integrity.mjs`、`skills/run-matt-spec-to-completion/lib/ticket-frontier.mjs` | state store 是唯一 writer；Checkpoint 保存同步状态、结构化双轴 Review Result、评审尝试和整合门禁，完整性校验 Git 身份、review range 和 fast-forward 条件。 |
| 测试 | `test/agent-workflow.test.mjs`、`package.json` | `package.json` 的 `test` 脚本使用 Node 测试运行器。 |
